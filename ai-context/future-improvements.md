# Материалы для сопроводительного письма

## Принятые трактовки ТЗ, которые нужно объяснить в письме

- **A-1. Члены семьи** — одна семья на инсталляцию, whitelist Telegram ID в конфиге (`ALLOWED_TELEGRAM_IDS`); пользователи регистрируются при первом сообщении. Почему: в ТЗ нет сущности семьи, это минимально достаточное решение. Развитие — мультисемейность и приглашения.
- **A-6. Удаление без подтверждения** — если трата определяется однозначно, бот удаляет и сообщает, что именно удалил; при неоднозначности переспрашивает. Почему: ТЗ требует «без кнопок», а лишний шаг подтверждения ухудшает UX частой операции. Развитие — soft-delete и «отмени последнее действие».
- **Наблюдение (BE-12)**: на тех же примерах ТЗ DeepSeek — 7/7 (~2 с/запрос), локальная `qwen2.5:3b` на CPU — ошибки категории и не исправляет «последнее» (15–30 с/запрос). Вывод: для агента с тулами нужна модель уровня DeepSeek; маленькая локальная — только запасной вариант. **Подтверждено eval (BE-11)**: DeepSeek 100% (135/135, 3 прогона, ~3 с), qwen2.5:3b — 56% (25/45), 28–70 с на CPU, хуже всего изменение (0/6) и удаление (1/5). **qwen2.5:7b** — 51% (23/45), 23–55 с: 13 из 22 провалов без единого вызова тула (3 — вызов напечатан текстом, 6 — ложное «Добавлена/Удалил»). Размер 3–7B для агента с тулами не годится.
- **Выбор LLM — DeepSeek** — доступен из РФ, дёшев, OpenAI-совместим (tool calling), открытые веса (MIT) → при требованиях 152-ФЗ разворачивается on-premise сменой `LLM_BASE_URL`. Честно указать: облачный API = трансграничная передача данных. Цифры eval: 100% на 45 сценариях (3 прогона), медиана 2.9 с; локальная 3B — 56%. Альтернативы: YandexGPT (конфиг), GigaChat (адаптер).

# Идеи на будущее

Копим по ходу работы. В конце отберём 5–7 самых сильных.

- **Eval-пайплайн в CI**: прогон набора фраз на каждый PR, отслеживание регрессий качества агента по моделям/промптам.
- ~~**MCP-сервер** с теми же тулами~~ — сделано в BE-13 (stdio). Дальше: Streamable HTTP-транспорт с авторизацией (один сервер на семью, пользователь из токена), `source = "mcp"` у трат (сейчас MCP-траты помечаются как `bot`).
- **Авторизация веб-панели** через Telegram Login Widget, роли «глава семьи / член семьи».
- **Мультивалютность** и курсы валют.
- **Бюджеты и уведомления**: лимит по категории, бот предупреждает о превышении.
- **Голосовые сообщения и фото чеков** (STT / OCR / QR-код чека ФНС).
- **Мультисемейность**: сущность «семья», приглашения по ссылке.
- **Self-hosted LLM** (DeepSeek/Qwen через vLLM) в контуре клиента — данные не покидают периметр.
- **Fallback-провайдер LLM**: при недоступности основного — переключение на резервный.
- **Оптимизация контекстного окна**: сейчас окно — последние N сообщений (целыми ходами). Дальше — сжатие старых ходов в краткое резюме, обрезка больших результатов тулов (list на 50 трат), учёт токенов вместо числа сообщений.
- **Метрики агента** (Prometheus/OTel): шаги на ход, частота ошибок тулов, токены и стоимость на пользователя, латентность LLM — чтобы видеть деградацию качества в проде, а не только в eval.
- **«Отменить» вместо подтверждения удаления** в веб-панели (мгновенное удаление + undo в уведомлении, требует soft-delete).
- **Eval — история для письма (BE-11)**: 45 сценариев на настоящем агенте, оценка по итоговому состоянию данных. Первый прогон нашёл опасную ошибку: модель отвечала «Удалил», не вызвав удаление (пользователь уверен, что трата удалена). Исправлено правилами промпта и подсказкой в результате поиска: DeepSeek 87% → 100%. Изоляция пользователей — 0 нарушений во всех 225 прогонах, даже у слабой модели, т. к. гарантируется типами, а не промптом. Дальше: `qwen2.5:7b`/14B на GPU для self-hosted, eval в CI, LLM-as-judge для текста ответов.
- **E2E и визуальные тесты фронта** (Playwright): основные сценарии в настоящем браузере + скриншотные сравнения на 390/768/1440 в обеих темах; axe в браузере — с контрастом и размером целей (в jsdom их не проверить). Сейчас: axe в Vitest + ручная сверка скриншотами (на 768 px так нашлась обрезанная сумма).
- **Предзагрузка ленивых частей** формы по наведению/фокусу на «Добавить трату» — первое открытие без задержки на медленной сети.
- **Разбор tool call из текста** для локальных моделей: Qwen 7B в Ollama иногда печатает `add_expense {…}` текстом вместо `tool_calls` — fallback-парсер превратил бы это в вызов (3 из 22 провалов 7B). Но главную ошибку — ложное «Добавлена» без вызова — он не лечит: нужна модель крупнее.
