# FE-03. Каркас страницы, шапка, состояние в URL, фильтры (десктоп)

**Оценка:** 3 ч · **Зависит от:** FE-02 · **Ветка:** `feature/FE-03-layout-filters`
**Дизайн:** артборды `Main`, `CategorySelect`; `design-spec.md` §4 «Шапка и фильтры», §5

## Цель
Страница с шапкой и рабочими фильтрами, состояние которых живёт в URL.

## Объём
- `useUrlState` — фильтры, сортировка, страница ↔ query (`user_id`, `from`, `to`, `period`, `category`, `sort`, `order`, `page`); значения по умолчанию: «Этот месяц», сортировка `spent_at desc`, страница 1; при смене фильтра страница сбрасывается на 1; невалидные значения из URL игнорируются.
- Layout: контейнер `max-w-[1280px] mx-auto`, поля `px-4 md:px-6 lg:px-8`.
- Шапка: заголовок «Семейные расходы», переключатель темы (Button `outline icon`, `Moon`/`Sun`, `aria-label`), кнопка «Добавить трату» (открывает диалог из FE-06).
- Фильтры (≥ `md`):
  - Select «Член семьи» с Avatar («Все члены семьи» + имена из `/api/users`);
  - Popover + Calendar `mode="range"`, `numberOfMonths={2}`, `locale={ru}`, подпись «1–31 окт 2026»;
  - ToggleGroup быстрых периодов (Сегодня · Неделя · Этот месяц · Прошлый месяц), ручной выбор дат снимает выделение;
  - Select «Категория» с цветной точкой;
  - «Сбросить» (`ghost`, `RotateCcw`) — только если фильтры отличаются от стандартных.
- Перенос строки фильтров по брейкпоинтам — как в `design-spec.md` §5.

## Критерии приёмки
- [ ] Тест `useUrlState`: чтение/запись, дефолты, сброс страницы, мусор в URL.
- [ ] Перезагрузка страницы сохраняет фильтры; ссылка с фильтрами открывается в том же состоянии.
- [ ] Визуально совпадает с артбордом `Main` (верхняя часть) в светлой и тёмной теме.

## Коммит
`feat(frontend): add page layout, header with theme toggle and URL-synced filters`

## Итог реализации (2026-10-16) — ✅ готово, ⏳ визуальная сверка пользователем

Проверено: `format:check` ✓, `typecheck` ✓, `lint` — 0, `test` — **72/72** (urlState 17, страница 7 — через MSW, с `Date`, зафиксированным на 2026-10-16), `build` ✓. Dev-сервер с моками: `http://localhost:5173` (контейнер `fe-dev`).

Что сделано:
- `features/expenses/urlState.ts` — состояние в URL: `user_id`, `from`/`to`, `category`, `sort` (`spent_at`/`amount`), `order`, `page`; значения по умолчанию в URL не пишутся (чистый адрес = «этот месяц, новые сверху, стр. 1»); мусор игнорируется (несуществующие даты вроде 2026-02-31, `from > to`, половина периода, `sort=id;drop`); любое изменение, кроме самой страницы, сбрасывает страницу на 1; `history.replaceState` (фильтры не засоряют кнопку «Назад»); `useSyncExternalStore` + `popstate`.
- `PageHeader` — заголовок, переключатель темы, «Добавить трату» (диалог — FE-06).
- `ExpenseFilters` — Select «Член семьи» с аватаром-инициалом; период: Popover + Calendar (2 месяца, `ru`), подпись «1–31 окт 2026»; быстрые периоды — ToggleGroup на `bg-muted`, активный `bg-card shadow-sm`, при ручном периоде выделение снимается; Select «Категория» с цветной точкой в порядке дизайна; «Сбросить» — только при нестандартных фильтрах.
- `ExpensesPage` — контейнер `max-w-[1280px]`, поля `px-4/6/8`; временная строка «Сводка по всем N тратам…» до FE-04/05.

Найдено тестами и исправлено:
- **Календарь «растягивал» текущий период**: при открытом «Этот месяц» клик по 5-му давал 1–5 вместо начала нового диапазона. Теперь клики интерпретируются явно (`onDayClick`): первый — начало, второй — конец (тот же день дважды — один день), затем применение и закрытие.
- Первая версия проверки даты из URL через `toISOString()` ломалась бы в UTC+3 — заменена на `parseISO` + `isValid` до написания тестов.

Отличия от плана:
- Параметр `period` в URL не нужен — пресет вычисляется по `from`/`to` (`matchPreset`).
- Мобильная версия фильтров (Drawer, чипы) — FE-08; пока строка фильтров переносится на узких экранах.
- `initials` вынесен в `shared/people.ts` (экспорт функции из файла компонента ломает Fast Refresh).
- Бандл вырос до 545 КБ (171 КБ gzip, предупреждение Vite > 500 КБ) — разбиение на чанки в FE-10.
