# BE-09. Агентский цикл, системный промпт, память диалога

**Оценка:** 3.5 ч (+0.5 ч — хранилище истории из BE-05) · **Зависит от:** BE-05, BE-08 · **Ветка:** `feature/BE-09-agent-loop`

## Цель
Агент, который по тексту пользователя вызывает тулы и отвечает по-русски; помнит контекст диалога.

## Объём
- `internal/agent`:
  - `Agent.Handle(ctx, user user.User, text string) (reply string, err error)`.
  - **Цикл**: system prompt + история + новое сообщение → `llm.Chat` → если есть tool calls: выполнить все (по порядку), добавить результаты → снова `llm.Chat`; максимум `AGENT_MAX_STEPS` шагов, иначе — вежливый ответ «не получилось, переформулируйте».
  - **Системный промпт** (`prompt.tmpl`, `text/template`): сегодня (дата + день недели), TZ, категории с примерами слов («кофе, продукты, ресторан → food»), правила:
    - не выдумывать сумму — переспросить;
    - относительные даты переводить в `YYYY-MM-DD` относительно «сегодня»;
    - для изменения/удаления сначала найти трату; если кандидатов несколько — перечислить и переспросить; если один — выполнить и сообщить, что сделано;
    - несколько трат в одном сообщении — несколько `add_expense`;
    - отвечать кратко, суммы в формате «1 200 ₽»;
    - нецелевые запросы — объяснить, что умеет бот;
    - данные других пользователей недоступны — так и сказать.
  - **Хранилище истории (перенесено из BE-05)**: интерфейс `agent.History { Append(ctx, userID, []llm.Message); Last(ctx, userID, n) ([]llm.Message, error) }` объявляется в пакете агента; реализации — `postgres.ChatHistoryRepo` (таблица `chat_messages`, `content` JSONB, sqlc-запросы, интеграционный тест) и in-memory в `memstore` (для тестов и eval).
  - **Память**: история из `History.Last(N)`; после ответа сохраняются все новые сообщения (user, assistant с tool calls, tool results, финальный ответ).
    - Обрезка истории **не разрывает** пару «assistant с tool_calls → tool results» (иначе API провайдера вернёт ошибку) — начало окна сдвигается до ближайшего `user`-сообщения.
  - **Последовательность**: мьютекс на `user_id` — сообщения одного пользователя обрабатываются по очереди.
  - `Clock` инжектится — для детерминированных тестов и eval.
  - Лог на каждый запрос: user_id, шаги, вызванные тулы, токены, длительность.

## Критерии приёмки (тесты на `llmtest.FakeClient` + fake-репозитории)
- [ ] «кофе 350» → один `add_expense`, ответ модели возвращён пользователю, история сохранена.
- [ ] Два tool calls в одном ответе выполняются и оба результата уходят в LLM.
- [ ] Превышение `AGENT_MAX_STEPS` → понятный ответ, без паники.
- [ ] Ошибка LLM → понятный ответ пользователю, ошибка в логе.
- [ ] Обрезка истории не оставляет «осиротевших» tool-сообщений (табличный тест).
- [ ] Системный промпт содержит подставленную дату из fake `Clock` (golden-тест).
