# BE-10. Telegram-бот `cmd/bot`

**Оценка:** 2 ч · **Зависит от:** BE-09 · **Ветка:** `feature/BE-10-telegram-bot`

## Цель
Бот в Telegram, который передаёт текст агенту и возвращает ответ. Без кнопок и команд (кроме автоматического `/start`).

## Объём
- `internal/telegram` на `github.com/go-telegram/bot`, **long polling**.
- Обработка апдейта:
  1. только текстовые личные сообщения; остальное (стикеры, фото, группы) → «Я понимаю только текст, например: кофе 350»;
  2. **whitelist** `ALLOWED_TELEGRAM_IDS`: посторонним — «Этот бот доступен только членам семьи», агент не вызывается;
  3. `user.Service.Upsert` (имя из `first_name + last_name`, `username`);
  4. `/start` → приветствие с примерами фраз (без вызова LLM);
  5. действие «печатает…» (`sendChatAction typing`), пока агент думает;
  6. `agent.Handle` → ответ **plain text** (без parse mode — не ломается на спецсимволах), разбиение на части > 4096 символов.
- `user_id` для агента берётся **только** из `update.Message.From.ID`.
- `cmd/bot/main.go`: конфиг → БД → репозитории → сервисы → LLM → агент → бот, graceful shutdown.
- Сервис `bot` в `docker-compose.yml`: команда `bot`, `depends_on: migrate (completed)`.

## Критерии приёмки
- [ ] Юнит-тест обработчика (агент и Telegram-клиент за интерфейсами): whitelist, не-текст, `/start`, длинный ответ режется.
- [ ] Ручная проверка в Telegram по всем примерам из ТЗ: «кофе 350», «такси 1200 вчера», «сколько потратил на еду в этом месяце», «покажи траты за неделю», «последнее было не 350, а 450», «удали такси».
- [ ] Ручная проверка изоляции: второй аккаунт не видит траты первого.

Проверено:

- **Примеры ТЗ на настоящей модели — ✅** (живой тест `internal/agent/live_test.go`, тег `live`, весь агент + DeepSeek + memstore, один диалог): «кофе 350» → 350 ₽ food сегодня; «последнее было не 350, а 450» → 450; «такси 1200 вчера» → transport 15.10; «сколько потратил на еду в этом месяце» → «450 ₽ (1 трата)»; «покажи траты за неделю» → список 12–18 октября без чужих трат; «удали такси» → удалено своё такси, чужое (у другого пользователя) цело; «купил продукты» → «Сколько потратил на продукты?», ничего не записано. 7 сообщений ≈ 13 с. Проверка в самом Telegram — за пользователем.

Что сделано:
- `internal/telegram.Handler` — логика без зависимости от библиотеки: игнор ботов/анонимов; только личные чаты; whitelist (посторонний — отказ + `warn` с его ID в логе, чтобы глава семьи мог добавить); `/start`, `/help` — приветствие с примерами без LLM; не-текст → подсказка; >1000 символов → отказ (бережём токены); upsert пользователя (имя + username из Telegram); «печатает…» обновляется каждые 4 с, пока думает агент; ответ агента (даже при ошибке — понятный текст).
- **Идентичность — только `update.Message.From.ID`**: единственный источник `user_id` для агента.
- Ответы — plain text (без parse mode: `*`, `_`, `<` от пользователя/модели ничего не ломают), разбиение > 4096 символов по строкам, по рунам (кириллица не рвётся), пробелы по краям обрезаются.
- `internal/telegram.Run` — `go-telegram/bot` v1.27, long polling, только `message`-апдейты, ошибки поллинга в лог.
- `cmd/bot` — сборка всего: Postgres → сервисы → LLM (DeepSeek, 2 ретрая) → агент (+ история в Postgres) → бот.
- Compose: сервис `bot` (без портов), `depends_on: migrate`.

Отличия от плана: добавлены `/help`, отказ в групповых чатах и лимит длины входящего сообщения.

Тест найденного: висячий `\n` в конце последней части длинного ответа — исправлено (`TrimSpace` перед разбиением).
