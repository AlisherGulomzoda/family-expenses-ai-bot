Привет! Тестовое готово: https://github.com/AlisherGulomzoda/family-expenses-ai-bot

Запуск — `cp .env.example .env`, токен бота и ключ DeepSeek, `docker compose up -d`; всё описано в README.

**Что сделано.** Telegram-бот с LLM-агентом (tool calling, память диалога) и веб-панель для главы семьи (React + TypeScript), REST по OpenAPI, PostgreSQL. Изоляция пользователей гарантируется типами, а не промптом: у тулов агента нет параметра, которым можно адресовать чужую трату. Суммы считает SQL, деньги — в копейках. Те же тулы отдаются MCP-сервером — к расходам можно подключить Claude Desktop или любого MCP-клиента без дублирования логики.

**Eval агента** — раз вы сейчас его пишете, сделал и здесь: 45 сценариев, оценка по итоговому состоянию данных. Первый прогон нашёл опасную ошибку — модель отвечала «Удалил», не вызвав удаление. После правок промпта DeepSeek проходит 100% (135/135 в трёх прогонах, ~3 с на сообщение), локальная Qwen 2.5 3B — 56%. Чужие данные не изменились ни в одном из 225 прогонов, включая prompt injection.

**Почему DeepSeek:** доступен из РФ, дёшев, OpenAI-совместимый tool calling, а открытые веса позволяют развернуть ту же модель в своём контуре, если важен 152-ФЗ (облачный API — это трансграничная передача). Модель меняется через `.env`, есть профиль с локальной моделью в Ollama.

**Две трактовки ТЗ, о которых стоит сказать:**
- *Члены семьи.* Сущности «семья» в ТЗ нет, поэтому одна семья на установку: список Telegram ID в конфиге, посторонним бот отказывает. Дальше — семьи и приглашения по ссылке.
- *Удаление в боте без подтверждения.* ТЗ просит «без кнопок», а лишний шаг на частой операции раздражает. Если трата однозначна — удаляю и пишу, что именно удалил; если нет — спрашиваю. Дальше — soft-delete и «отмени последнее».

**Что сделал бы дальше:**
1. Eval в CI на каждый PR — регрессии качества агента видны до релиза.
2. Бюджеты и уведомления: лимит по категории, бот сам предупреждает о превышении.
3. Окно контекста: сжатие старых ходов в резюме, обрезка больших результатов тулов, лимит по токенам.
4. Метрики агента: шаги на ход, ошибки тулов, токены и стоимость, латентность.
5. Self-hosted модель крупнее (7–14B на GPU) и резервный провайдер LLM.
6. Авторизация панели через Telegram Login и роли.

Весь процесс — бэклоги, тикеты, решения и работа с ИИ-ассистентом — лежит в `ai-context/` и описан в README.
