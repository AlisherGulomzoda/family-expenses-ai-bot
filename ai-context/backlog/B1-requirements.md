## 1. Функциональные требования

### FR-1. Модель данных «Трата»
| Поле | Тип (предв.) | Правила |
|---|---|---|
| `id` | bigint / uuid | генерирует БД |
| `user_id` | bigint | Telegram ID владельца, обязателен |
| `amount` | decimal(12,2) / копейки | > 0, рубли |
| `category` | enum | еда, транспорт, жильё, развлечения, здоровье, покупки, другое |
| `spent_at` | date | по умолчанию — сегодня (в TZ пользователя) |
| `comment` | text, nullable | описание траты («кофе», «такси») |
| `created_at`, `updated_at` | timestamptz | ставит бэкенд |

### FR-2. Telegram-бот (естественный язык, без кнопок и команд)
| # | Операция | Примеры из ТЗ | Ожидаемое поведение |
|---|---|---|---|
| FR-2.1 | Добавить | «кофе 350», «такси 1200 вчера» | Определить сумму, категорию, дату, комментарий; ответить подтверждением |
| FR-2.2 | Посмотреть | «сколько потратил на еду в этом месяце», «покажи траты за неделю» | Список и/или сумма за период, с фильтром по категории |
| FR-2.3 | Изменить | «последнее было не 350, а 450» | Найти нужную трату (по контексту диалога/последней), изменить поле |
| FR-2.4 | Удалить | «удали такси» | Найти трату; если однозначно — удалить и сообщить что удалено; если несколько — переспросить |
| FR-2.5 | Изоляция | «Чужие траты в боте недоступны» | Любая операция бота работает **только** с тратами отправителя |
| FR-2.6 | Нецелевые сообщения | «привет», «какая погода» | Вежливо объяснить, что умеет бот (неявное требование) |

### FR-3. Веб-панель главы семьи

| FR-3.6 | Работа только через REST API бэкенда |

## 3. Неоднозначности ТЗ и предлагаемая трактовка

| # | Вопрос | Предлагаемое решение |
|---|---|---|
| A-1 | Кто такие «члены семьи»? В ТЗ нет сущности семьи | Одна семья на инсталляцию. Таблица `users` (telegram_id, имя из профиля TG) заполняется при первом сообщении. Опционально `ALLOWED_TELEGRAM_IDS` в конфиге — бот игнорирует посторонних |
| A-2 | Как веб-панель создаёт трату для члена семьи, который ещё не писал боту? | Выбор только из известных пользователей (`users`). Добавление пользователя вручную — не делаем (в «будущее») |
| A-3 | Валюта | Только рубли, без мультивалютности |
| A-4 | Таймзона для «вчера», «в этом месяце» | Одна TZ из конфига (по умолчанию `Europe/Moscow`) |
| A-5 | «Последнее» в FR-2.3 — последнее по `created_at` или по `spent_at`? | По `created_at` (последняя добавленная) + учитывать контекст диалога |
| A-6 | Подтверждение удаления | Без подтверждения, если однозначно; бот пишет, что удалил (сумма, категория, дата). Переспрашивает только при неоднозначности |
| A-7 | Неполные данные («кофе» без суммы) | Бот переспрашивает, не сохраняет трату с выдуманной суммой |
| A-8 | Несколько трат в одном сообщении («кофе 350, такси 500») | Поддерживаем — агент вызывает тул несколько раз |
| A-9 | Категория неочевидна | Агент выбирает ближайшую, иначе «другое»; пользователь может исправить |
| A-10 | Удаление: физическое или мягкое | Физическое (ТЗ просит CRUD; soft-delete — в «будущее») |
| A-11 | Память диалога | Храним последние N сообщений чата, чтобы работали «последнее», «то же самое» и уточнения |
| A-12 | Веб-панель без авторизации, но в публичном доступе — риск | Принимаем как в ТЗ, явно указываем в README и письме |
