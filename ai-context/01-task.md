# Суть задания и контекст работодателя

Полный текст ТЗ: `test-task-expenses.md` (корень директории).

## Работодатель (из письма рекрутера, кратко)

- Продукт: мониторинг промышленного оборудования, предиктивная аналитика, ИИ-чат с доступом к любой функции системы **через MCP**.
- Стек: микросервисы на Go, Kafka, PostgreSQL, LLM, RAG, Docker.
- Их текущие боли: качество ответов агента (тулы, контекстное окно, RAG), **пишут eval** для агента.
- Клиент/работодатель находится в РФ → LLM должна быть доступна из РФ (см. решения).
- Результат: ссылка на репозиторий в чат + сопроводительное письмо с планом улучшений.

## ТЗ в двух словах

- Сущность «Трата»: id, user_id (Telegram ID), amount, category (еда, транспорт, жильё, развлечения, здоровье, покупки, другое), spent_at, comment?, created_at, updated_at.
- Telegram-бот: CRUD на естественном языке, без кнопок и команд. Только свои траты.
- Веб-панель главы семьи: CRUD по всем тратам, фильтры (член семьи, период, категория), REST API, без авторизации.
- Go-бэкенд, любой фронт, всё поднимается одним `docker compose`, LLM настраивается конфигом.
- Оценивают в том числе качество использования ИИ-ассистентов.

## Что, вероятно, оценивают сильнее всего

1. Архитектура агента (tool calling, а не парсинг JSON).
2. Изоляция данных пользователей на уровне кода, а не промпта.
3. Работа с ИИ-ассистентом (прозрачный процесс — эта папка `ai-context/`).
4. Качество Go-кода, тесты, compose, README.
5. Бонус, попадающий в их боли: eval-набор для агента, MCP.
