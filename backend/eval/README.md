# Eval агента

Набор из 45 сообщений пользователя (`cases.yaml`), которые прогоняются через **настоящего агента** (системный промпт, тулы, память диалога) и **настоящую LLM** на хранилище в памяти (`internal/memstore` — та же семантика, что у Postgres, проверено общим контрактным тестом).

## Как оценивается кейс

Не по точным аргументам тулов (к одному результату модель может прийти разными путями), а по **данным, которые остались после ответа**, и по самому ответу:

1. ожидаемые изменения: добавлено / изменено / удалено (сумма, категория, дата, комментарий);
2. **никаких побочных эффектов**: остальные траты не изменились, лишних не появилось;
3. **траты другого члена семьи не тронуты** — проверяется в каждом кейсе;
4. нужные тулы вызваны (например, `summarize_expenses` для «сколько…», чтобы суммы считал SQL, а не модель);
5. ответ: содержит верные суммы (`3 830,50 ₽` ≙ `3830.50`), нужные слова, не содержит чужих данных, задаёт вопрос, когда должен уточнить.

«Сегодня» зафиксировано (пятница, 2026-10-16, Europe/Moscow) — относительные даты проверяются точно.

Группы (теги): `add` 15, `dates` 11, `read` 9, `update` 6, `delete` 5, `clarify` 4, `security` 4, `offtopic` 3, `multi` 3 (у кейса может быть несколько тегов).

## Запуск

```bash
make eval                         # LLM из ../.env (по умолчанию DeepSeek)
make eval ARGS="-runs 3"          # 3 прогона на кейс — стабильность ответов
make eval ARGS="-tags read,dates" # только группы
make eval ARGS="-case update-last-amount"
```

Отчёт — `eval/reports/<модель>-<дата>.md`: процент, по тегам, латентность, токены, разбор каждого упавшего кейса (вызовы тулов с аргументами, ответ, что не так).

## Результаты

| Модель | Где работает | Прогонов | Проходит | Латентность (медиана / p90) | Отчёт |
|---|---|---|---|---|---|
| DeepSeek `deepseek-chat`, исходный промпт | облако | 45 × 1 | 87% (39/45) | 2.4 / 4.2 с | [1-baseline](reports/deepseek-chat-1-baseline.md) |
| **DeepSeek `deepseek-chat`, после правок** | облако | 45 × 3 | **100% (135/135)** | 2.9 / 5.0 с | [2-prompt-fix](reports/deepseek-chat-2-prompt-fix.md) |
| Qwen 2.5 3B через Ollama (тот же промпт) | локально, CPU | 45 × 1 | 56% (25/45) | 27.6 / 69.4 с | [qwen2.5-3b](reports/qwen2.5-3b.md) |
| Qwen 2.5 7B через Ollama (тот же промпт) | локально, CPU | 45 × 1 | 51% (23/45) | 23.0 / 54.6 с | [qwen2.5-7b](reports/qwen2.5-7b.md) |

**Безопасность**: во всех 270 прогонах (все строки таблицы) — **ни одного изменения чужих трат**, включая кейсы с prompt injection и попыткой удалить трату по чужому id. Это не заслуга модели: у тулов просто нет параметра, которым можно адресовать другого пользователя (`expense.UserScope`). Слабая модель ошибается в данных *своего* пользователя (записала «кофе 300 на Мадину» на Алишера), но до чужих не дотягивается.

### Выводы для выбора модели

- **DeepSeek достаточно для этой задачи**: 100% на 45 кейсах в 3 прогонах (стабильно), ~3 с на сообщение, ~5.3k токенов на входе и ~100 на выходе (основная часть входа — системный промпт и схемы тулов, одинаковые для всех сообщений).
- **Локальные Qwen 2.5 3B и 7B не годятся как основная модель**: 56% и 51% (на одном прогоне из 45 кейсов разница в пределах шума), 23–70 с на сообщение на CPU. Хуже всего изменение (0/6 и 1/6) и удаление (1/5 у обеих). У 7B 13 из 22 провалов — ответ **без единого вызова тула**: 3 раза вызов напечатан текстом (`add_expense {…}`), и Ollama не распознала его как tool call; **6 раз — ложное подтверждение** («Добавлена трата», «Удалил»), та же ошибка, что eval нашёл у DeepSeek до правок промпта; остальное — «Покажу траты…» без вызова и лишние переспрашивания. Профиль `local-llm` оставлен для работы без внешних API; для self-hosted нужен класс крупнее (Qwen 2.5 14–32B, DeepSeek на GPU) — следующий шаг сравнения.
- Цифры по тегам и разбор каждой ошибки — в отчётах.

### Что нашёл первый прогон и что исправлено

| Проблема | Пример | Исправление |
|---|---|---|
| **Модель сообщала о действии, которого не было**: нашла трату через `list_expenses` и ответила «Удалил/Изменил», не вызвав `delete_expense`/`update_expense` (3 кейса) | «удали такси» → «Удалил трату: такси, 1 200 ₽» — трата на месте | Главное правило в промпте («данные меняют только add/update/delete; не пиши “удалил”, пока тул не вернул успех»), подсказка прямо в результате `list_expenses`, уточнение в описании тула |
| «кино было 1200» записано как **новая** трата вместо исправления | | Правило: «X было N» — исправление существующей траты |
| «в субботу» (сегодня пятница) → **будущая** суббота 17.10 | | В промпт подставлены даты последних 7 дней с днями недели (считает Go) |
| «потратил 500» — модель переспросила, а кейс ждал запись в «другое» | | Продуктовое решение: без описания — уточнять (кейс переписан, это не подгонка: записать безымянную трату хуже) |
